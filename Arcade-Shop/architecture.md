# Architecture — Arcade Vault

Next.js 16 (App Router) e-commerce site for a retro/arcade game store.
Server-rendered pages, client-driven game catalog, no backend API.

## Layout

```
src/
  app/
    (pages)/          # home — hero, genre grid, featured, newsletter
    g/[slug]/         # game detail (the canonical game route)
    shop/ categories/ best-sellers/ new-releases/ top-rated/
                    sale/ search/ cart/ wishlist/ account/
    about/ accessibility/ privacy/ terms/ cookies/
    blog/ press/ careers/ help/ refunds/ shipping/ faq/ contact/
  components/
    layouts/          # Navbar, Footer
    providers/        # Providers (auth, theme, cart, wishlist, user)
    ui/               # Button, Card, Input (shared primitives)
    arcade/           # Hero, GameGrid, CookieBanner, NewsletterForm, ...
    legal/            # LegalPage
  context/            # CartContext, WishlistContext, GameContext, UserContext
  hooks/
  lib/                # games-data.ts, utils.ts
  types/              # Game, GameCategory, Platform, ...
content/
  games/games.json    # source of truth for the catalog (6 games)
public/
  images/games/<slug>/ # hero + screenshots (generated by generate_arcade_images.py)
  icons/ favicon.ico apple-touch-icon.png site.webmanifest
```

## Data flow

The catalog lives in `content/games/games.json` and is **not** fetched from an
API. On client hydration, `window.__arcadeGames` is populated (see
`src/lib/game-globals.d.ts`) so pages can read it without a server request.

- `src/lib/games-data.ts` reads the payload and exposes `useGamesData()` +
  filter/sort helpers (`getFeaturedGames`, `getNewReleases`, `getTopRated`,
  `getOnSale`, `searchGames`).
- `GameContext` (`src/context/GameContext.tsx`) is a typed reducer store
  (`SET_GAMES`, `SET_CATEGORY_FILTER`, `SET_SEARCH`, `SET_SORT`, …) that pages
  and components consume. `Providers` wraps the whole app.
- Pages use `useGamesData()` directly for read-only listings.

## Design system (Tailwind v4)

All styling is tokenized in `tailwind.config.ts`:

- **Colors** → `arcade.bg.{deep,elevated,card}`, `arcade.fg.{primary,muted}`,
  `arcade.accent.{pink,blue,green,yellow,purple}`, `arcade.border.glow`.
- **Fonts** → `font-display` (Space Grotesk), `font-body` (Outfit), `font-mono`
  (JetBrains Mono). Fonts are Next `next/font/google` variables (see
  `layout.tsx`).
- **Spacing** → custom `space-1..space-5` (4px base).
- **Utility classes** used across the app: `bg-arcade-bg-card`,
  `rounded-arcade-lg`, `card-glow`, `text-arcade-fg-primary`, `font-display`,
  `font-mono`, `text-arcade-accent-pink`.

## Key constraints / gotchas

- **Game route is `/g/[slug]`**, not `/game/[slug]`. Links must use `/g/${slug}`.
- `react-hooks/set-state-in-effect` is allowed in `games-data.ts` (documented
  hydration pattern: synchronizing state with an external payload).
- `@react-three/fiber`/`@react-three/drei` throw false-positive lint errors;
  they are disabled per-file.
- No `next lint` binary in the ESLint 9 flat-config sense — `npm run lint`
  runs `next lint` (Next 16 ships its own ESLint plugin).
- `react/no-unescaped-entities` requires HTML entities (`&ldquo;`, `&apos;`,
  or single quotes) in string content.
